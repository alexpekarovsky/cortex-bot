# Cortex MCP - Bug Tracker

## BUG-001: `list_integrations` and `get_integration_commands` fail with 500 on `/settings/integration-search`

**Date:** 2026-02-26
**Severity:** Medium
**Status:** Fixed
**Affected file:** `src/usecase/custom_components/integration_discovery.py`

### Description

Both `list_integrations` (line 60) and `get_integration_commands` (line 157) call the endpoint `POST /public_api/v1/settings/integration-search`. This endpoint consistently returns a `500 Internal Server Error` on certain XSIAM tenants.

### Error

```
Server error for request to /public_api/v1/settings/integration-search: Internal Server Error
The server encountered an unexpected internal server error
(generated by waitress) [500]
```

### Root Cause

The `/settings/integration-search` endpoint appears to be unreliable or unsupported on certain XSIAM tenant versions/regions. This is a server-side issue — the request format is correct.

### Proposed Fix

Replace the direct API call with the XSOAR automation command `!GetInstances` executed via the War Room (same approach used by `run_xsoar_automation`). This is more reliable because it goes through the XSOAR engine rather than the public API settings endpoint.

**Current approach (broken):**
```python
endpoint = "/settings/integration-search"
response = await fetcher.send_request(path=endpoint, method="POST", data=request_data)
```

**Proposed approach:**
```python
# Use run_xsoar_automation internally to execute !GetInstances
# Then parse the War Room response to extract integration info
command = '!GetInstances instance_status="active"'
# Execute via War Room entries API (which works reliably)
```

### Steps to Reproduce

1. Connect to any XSIAM tenant with a valid API key
2. Call `list_integrations()` or `get_integration_commands("VirusTotal")`
3. Observe 500 error

### Fix Applied

Both functions now try the API endpoint first, then automatically fall back to `!GetInstances`
via War Room if it returns a 500 error. Optional `alert_id`/`case_id` parameters added for the
fallback path. If no ID is provided and the API fails, the error message includes the workaround.

### Previous Workaround (before fix)

Use `run_xsoar_automation` with `!GetInstances` to list integrations manually:
```
run_xsoar_automation(command='!GetInstances instance_status="active"', case_id="<any_case_id>")
```
